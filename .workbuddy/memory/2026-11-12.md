## 接入 Aspire 本地编排（一条命令启动全栈）

- 新增 `src/ShortLink.AppHost`（`<Project Sdk="Aspire.AppHost.Sdk/13.6.5">`，Aspire.Hosting.MySql/Redis/Kafka 13.6.5 已写入 CPM），加入 `ShortLink.slnx`。
- 命令：`dotnet run --project src/ShortLink.AppHost` → 仪表盘 15000、API 5080、Web 5081；Docker 拉起 MySQL 8.4 + Redis。
- 设计约束（已写入 AGENTS.md 与 ADR 0010）：
  - 只有 AppHost 引 `Aspire.Hosting.*`，应用项目零 Aspire 依赖，只吃 `IConfiguration`（`Database__*` / `Cache__RedisConnectionString` / `Messaging__*`）。
  - 不引 ServiceDefaults：Api 自有 OTel 三信号与 `/health` 语义（存活探针不查依赖）。
  - 对外端口固定 5080/5081（WASM `ApiBaseUrl` 与 CORS 是浏览器读的静态配置）；容器与 Aspire 内部端口一律自动分配。
- 实测踩到的三个坑（已在代码注释与 ADR 记录）：
  1. `launchSettings.json` 不允许 JSON 注释，`dotnet run` 会整份忽略启动配置文件（表现为仪表盘跑到随机 https 端口）。
  2. Aspire 要求 dashboard 地址是 https，否则需 `ASPIRE_ALLOW_UNSECURED_TRANSPORT=true`。
  3. 不要固定 `ASPIRE_RESOURCE_SERVICE_ENDPOINT_URL`：本机 20000 被 SangforPromote.exe 占用；另外 Aspire 的 Redis 容器默认 `requirepass`，连接串必须用 `RedisResource.ConnectionStringExpression`（自己拼 `host:port` 会让 `/health/ready` 的 cache 一直 fail）。
- 验证：MySQL 路径（/health/ready=ready、登录→建链→302→clickCount=1）与 sqlite/no-redis 降级路径均通过；`dotnet test` 140 全绿。
- 新增 `tests/ShortLink.ArchitectureTests/PackageReferenceTests.cs`：扫描 csproj，禁止应用项目引用 `Aspire.*` 包（ArchUnitNET 看不到未使用的包引用）。
- 文档：`docs/adr/0010-aspire-apphost-orchestration.md`、README 快速开始第 1 节、AGENTS.md「本地编排」小节、根目录 `aspire.config.json`。

## 发布端：产出 compose / Helm（同一天续）

- 新增 `Aspire.Hosting.Docker` 13.6.5 + `Aspire.Hosting.Kubernetes` 13.6.5-preview.1.26559.7（CPM 已登记，K8s 仍是 preview）。
- 新增本地工具 `aspire.cli` 13.6.5（`.config/dotnet-tools.json`），命令：
  - `dotnet aspire publish -o artifacts/compose`（实测 7/7 步骤成功，产出 docker-compose.yaml + .env）
  - `ShortLink__PublishTarget=kubernetes dotnet aspire publish -o artifacts/k8s`
  - `dotnet aspire do build-api|build-web|prepare-shortlink`、`dotnet aspire deploy`
- 关键结论（写入 ADR 0011 与 AGENTS.md）：
  - 一次只能挂一个 compute environment（`validate-compute-environments`）；目标用配置 `ShortLink:PublishTarget` 选，CLI 的 `aspire publish` **没有** `--publisher` 参数。
  - `publish` 只出文件不建镜像：`.env` 里 `API_IMAGE/API_PORT` 为空是设计如此，要镜像得跑 `prepare-*`/`deploy`。
  - publish 模式密钥一律不给默认值（jwt-signing-key / seed-admin-password / mysql-password / default-domain-host），产物留占位符。
- 新增 `src/ShortLink.Web/Dockerfile`（SDK 构建 + nginx 托管，两段式）+ `nginx.conf`（SPA 回落、框架文件 no-cache）；AppHost 用 `PublishAsDockerFile(...WithDockerfile(contextPath:"../.."))` 指过去，避免 DevServer 混进生产镜像。
- compose 产物在 `ConfigureComposeFile` 里补：MySQL healthcheck + api `depends_on: service_healthy`、端口映射去重（Aspire 会同时生成 `5080:8080` 与裸 `8080`）、dashboard 默认关闭。
- Api 侧 OTel 端点改为「`OpenTelemetry:Endpoint` 优先、`OTEL_EXPORTER_OTLP_ENDPOINT` 兜底」，并按 `OTEL_EXPORTER_OTLP_PROTOCOL` 选 gRPC/http-protobuf（新增 `using OpenTelemetry.Exporter;`）。
- 实测：`api:latest` 镜像构建成功（481MB）；web 镜像构建在本机卡在容器内 NuGet restore（Docker Hub 曾报 Bad Gateway，重试后 nginx 拉取成功但仍慢），未跑完；run 模式回归（5080/5081/15000 + ready）正常；`dotnet test` 140 全绿。

- 上线阻断项：基础 `appsettings.json` 含公开固定 JWT 密钥与 owner 初始密码；JWT 无改密/停用/降权后的撤销；用户管理缺工作区过滤；工作区 admin 可改全局域名；compose 开启宽泛 Forwarded Headers 且直连 API 端口。
- 关键缺陷：fallback/条件路由绕过 UrlScanner；Kafka 点击无幂等键会重复计数；ConversionRepository 把所有 DbUpdateException 当重复成功；举报自动停用因 AsNoTracking 实际无效（修复时须同时默认关闭单举报停用，避免引入匿名 DoS）；域名停用不影响 Host 解析且缓存未失效。
- 主要性能/一致性：点击封顶不是原子准入；趋势 UV 将去重对拉入内存；转化回调每次汇总全历史；保留清理缺 `(clicked_at_utc,id)` 索引且无跨副本协调；CSV 下载会把 HTTP 200 JSON 错误信封保存为成功文件。
- 本次未做压测、EXPLAIN 或真实 Kafka 验证，性能结论均为源码静态推导。
