# 2026-11-11 · ShortLink 平台从骨架到可运行

## 背景
用 .NET 10 + Minimal API + Blazor WASM(MudBlazor) + MySQL 实现自建短链平台。仓库原有 12 个空项目骨架（零 .cs），本次完成全部实现并跑通。

## 已完成
- **分层**：Contracts（信封/业务码/DTO，前后端共享）→ Domain（零框架）→ Application（端口 + 用例 + FluentValidation）→ Infrastructure（EF Core/JWT/FusionCache/点击批处理）→ Api（端点 + 收口）→ Web（WASM + MudBlazor）。
- **契约**：HTTP 200 + `{code,msg,data}`，`BizCodes` 分段码表，`BusinessException`，唯一 `IExceptionHandler`；401/403/429/404/405 与 API 版本、限流拒绝全部归一化。跳转与 /health 是显式例外（保留真实 HTTP 语义）。
- **跳转链路**：Host+Code → 域名缓存（未匹配回落默认域名）→ 短链缓存（负缓存防穿透）→ 回源；302/301/307/308；停用/过期/密码走品牌化 HTML 落地页（404/410/200 密码表单）。
- **统计**：点击入有界 Channel（2 万，丢弃计数），后台 500/批 + 500ms 聚合窗口，事务内 `ExecuteUpdate` 增量计数 + 批量插入；聚合下推到 SQL（按 `click_date` 索引），独立访客用 IP+UA+日期 SHA256 去重。
- **MySQL**：`Microting.EntityFrameworkCore.MySql` 10.0.14（MIT，Pomelo 分支，命名空间仍是 `Microsoft.EntityFrameworkCore`），三套迁移程序集（Sqlite/MySql/PostgreSql），API 显式引用三者否则 MigrateAsync 反射加载失败。
- **前端**：登录、控制台（KPI + CSS 趋势图 + 热门短链）、短链管理（ServerData 表格 + 对话框 CRUD + 复制/启停/统计）、域名管理、单链统计；JWT 存 localStorage，ApiClient 按 code 判定并处理 40101。

## 关键坑（已解决）
- `ShortLink` 实体名与根命名空间冲突 → 实体改名 `Link`。
- .NET 10 下 `dotnet test` 默认 VSTest 与 xunit.v3(MTP) 冲突 → `global.json` 加 `"test": { "runner": "Microsoft.Testing.Platform" }`，并移除 Test.Sdk / runner.visualstudio。
- `UseExceptionHandler()` 无参需兜底委托 → 配置 `ExceptionHandlerOptions.ExceptionHandler`。
- WebApplicationFactory 的 `ConfigureAppConfiguration` 晚于 Program 的即时读配置 → 改为运行时解析（`AddDbContext((sp,o)=>...)` + `AddOptions<JwtBearerOptions>().Configure<IOptions<JwtOptions>>`）。
- Blazor WASM 默认不含 Authorization 组件 → 加 `Microsoft.AspNetCore.Components.Authorization` 10.0.15。
- MudBlazor 9 API：`ShowMessageBoxAsync`、`ISnackbar.Add(...)`，`@bind-Value` 与 `ValueChanged` 不可同时出现。

## 工程化加固（P3 首轮）

延续「继续完善」，处理 4 个上线后会真出事的默认值问题，全部落到代码 + 测试 + 文档：

### 1. 限流分区（原实现是错的）
- 旧：`AddFixedWindowLimiter("auth")` —— **全进程共享一个窗口**，任何人刷 10 次错误登录就能把其他所有用户挡在门外；多实例下实际配额 = 阈值 × 实例数。
- 新：`RateLimitingSetup.CreatePartition` 以 `{policy}:{clientIp}` 为分区键走 `RateLimitPartition.Get`（用 Get 而非 GetFixedWindow，是为了在工厂里按「是否配置 Redis」动态选实现）。
- 阈值改为在 options 解析阶段读取（`AddOptions<RateLimiterOptions>().Configure<IOptions<RateLimitOptions>>`），否则测试宿主/容器的配置覆盖不生效。
- Redis Lua 单脚本 `INCRBY` + `PTTL` + 按需 `PEXPIRE`：不用两步 INCR/EXPIRE，避免中间崩溃或主从切换丢掉 EXPIRE 后留下无 TTL 键把 IP 永久封死。`PTTL<0` 同时覆盖「键不存在(-2)」与「无过期(-1)」。
- Redis 异常 → 回落 `FixedWindowRateLimiter` + `shortlink.ratelimit.fallbacks` 累加。三选一里刻意排除「放行」（打挂 Redis 即绕过限流）与「全拒」（Redis 抖动变全站不可用）。
- `IdleDuration => Window * 2`：分区键按 IP 增长，不设空闲回收会让 RateLimiter 的内部字典持续膨胀。

### 2. 点击明细保留策略
- `ClickRetentionService : BackgroundService`，默认**关闭**（删数据不可逆）。启动延迟 2min、每 15min 轮询、按 UTC 日期去重，避免重启重复跑。
- 过滤用 `ClickedAtUtc`（索引前缀）而非 `ClickDate`（受统计口径调整影响）。
- **先取主键再按主键删**，不复用一条大 DELETE：千万行表单条 DELETE 长事务锁表 + 复制延迟飙升。
- 三重上限：`BatchSize`（clamp 50~2000，受 SQL 变量上限）、`MaxRowsPerRun`、`BatchDelayMilliseconds`。
- `PurgeAsync` 设为 public：调度壳只负责触发，测试直接驱动并断言行数，不用改系统时间。

### 3. 探针分层
- `/health` 只证明进程活着，**刻意不查 DB**：数据库抖动 30s → 全体实例重启 → 故障放大成雪崩。
- `/health/ready` 查 DB + `ICacheHealthProbe`，失败返回 503 + 纯文本 `database=ok,cache=fail`（定位不用翻日志）。
- `RedisCacheHealthProbe` 在未注册 `IConnectionMultiplexer` 时恒健康：没配 Redis 是「不需要缓存」不是「缓存挂了」。

### 4. 权限收口
- `DomainEndpoints` / `AnalyticsEndpoints` / `AuthEndpoints(/me,/change-password)` 补命名策略；域名写操作收到 `Manager`。

### 踩坑
- `RateLimiterOptions` 在 `Microsoft.AspNetCore.RateLimiting` 命名空间，不在 `System.Threading.RateLimiting` → 补 using 即修好（唯一编译错误）。
- xUnit v3 用 `TestContext.Current.CancellationToken`。
- `ApiResponse<T>` 没有 `Success` 属性，断言写 `Code == BizCodes.Success`；登录返回类型是 `LoginResponse` 不是 `LoginResult`。

- `dotnet build` 0 error；`dotnet test` **95/95**（新增 4 条：viewer 越权 40301、/health 与 /health/ready、Purge 只删过期、保留策略默认关闭）。

## MCP Server（AI 客户端接入）

新增 `src/ShortLink.Mcp`（独立程序集，与 HTTP 端点平级的入口适配层），把短链能力暴露给 AI 客户端。**默认关闭**（`Mcp:Enabled=false`）。

### 包与版本
- `ModelContextProtocol.AspNetCore` **2.4.0**（2026-11-11 通过 nuget.org flat container 核实；api.nuget.org 302 到 nuget.azure.cn，curl 要 `-L` 跟镜像）。
- 2.x 断代：`HttpServerTransportOptions.Stateless` 默认已是 true（显式写出以留决策痕迹）；`McpServerToolAttribute` 新增 `ReadOnly`/`Destructive`/`Idempotent`/`OpenWorld` 注解。

### 结构
- `Tools/LinkTools`（create/get/list/set_enabled/delete）、`AnalyticsTools`（stats/dashboard/recent_clicks）、`DomainTools`（list_domains）= 9 个工具。
- `Tools/McpToolRunner`：鉴权（`UserRoles.AtLeast`）→ 执行 → 异常映射 → 埋点/审计。**工具异常必须映射为 `McpException`**，否则业务码全丢；`IExceptionHandler` 管不到工具。
- `Models/McpContracts.cs`：精简 record（`LinkSummary` 14 字段 vs `LinkDto` 30 字段），趋势默认不返回、维度只回 TopN、点击明细不含原始 IP。
- `Diagnostics/McpDiagnostics`：`shortlink.mcp.tool_calls` / `tool_duration` / `tool_rejections` + ActivitySource，标签 `mcp.tool.name` / `is_error` / `mcp.biz_code`。

### 应用层新增
- `LinkService.GetByShortUrlAsync(shortUrlOrCode)` —— 模型手里通常只有 URL 没有 ID；短码只在域名内唯一，带 URL 时必须用 Host 定位域名（`uri.IsDefaultPort` 要处理，否则带端口的部署匹配不上），只给短码时要求工作区仅一个域名。
- `LinkService.SetEnabledAsync(id, bool)` —— 幂等设状态。原来工具里「先 Get 再 Toggle」在两个相反请求并发时会翻转两次回到原状态，是真并发缺陷；领域层 `Enable/Disable` 已存在，直接复用。

### 踩坑（重要）
1. **401 有两道关**：只把 `/mcp` 加进 `ResponseNormalizationMiddleware` 白名单不够——401/403 是 `JwtBearerEvents.OnChallenge/OnForbidden` **直接写信封**的，绕过中间件。第一版实测匿名请求仍返回 `200 + {code:40101}`。必须在 challenge 事件里判路径并保留 401 + `WWW-Authenticate: Bearer`。
2. **回归测试要断言真实状态码**，不能断言「客户端抛异常」：两种实现下 `McpClient.CreateAsync` 都会失败（信封也解析不出 JSON-RPC），断言 401 才防得住。
3. **启用开关不能在服务注册阶段读**：`AddShortLinkMcp` 若按 `Mcp:Enabled` 提前 return，容器 `Mcp__Enabled=true` 与测试宿主的 `AddInMemoryCollection` 都晚于注册，端点会静默消失。开关只在 `app.MapMcp` 时读。
4. **工具类必须注册为 scoped**：SDK 默认 transient，注入 scoped 的 `LinkService` 会抛 "Cannot resolve scoped service from root provider"。用 `services.AddScoped<LinkTools>()` 覆盖。
5. **`CallToolResult.IsError` 是 `bool?`**，成功时为 null；测试里 `Assert.False(x.IsError)` 会失败，要写 `Assert.NotEqual(true, x.IsError)`。
6. **`curl -d` 里嵌套引号**导致登录请求失败，改用 python 脚本做探测。
7. `initialize` 传错 `protocolVersion`（2026-07-28）会返回 `-32022`，但 Stateless 模式下后续 `tools/list` 仍可用；真实 `McpClient` 会自动协商。

### 刻意偏离规范
- 参数非法统一走 `IsError`（`40001`）而非 `McpProtocolException`（-32602）：校验在应用层 FluentValidation，拆两套语义会出现「同一空值有时协议错、有时业务错」。代价是占一轮模型推理。已写入 ADR 0007。

## 引入 Wolverine 消息总线（点击落库 + 封顶审计）

用 `WolverineFx 6.64.0` 取代手写的 `ClickEventQueue` + `ClickEventFlushService`（进程内 `Channel<ClickEvent>`）。三个维度设计上互相独立：`Messaging:Transport`（local/kafka，决定发去哪）、`Messaging:Durable`（是否走 outbox）、`ClickBatchSize`/`ClickBatchTimeoutMilliseconds`（攒批，默认 500 条 / 500ms）。

### 新增/修改文件
- `src/ShortLink.Application/Messaging/MessagingContracts.cs`：`ClickRecorded` / `LinkClickCapped` / `LinkDisabled` + `From/ToEntity` 投影、`LinkDisableReasons`。
- `src/ShortLink.Infrastructure/Options/MessagingOptions.cs`：三个开关 + `Validate()`（启动期抛，不等到第一次跳转）+ `TopicFor(name)`。
- `src/ShortLink.Infrastructure/Messaging/MessagingSetup.cs`：`AddShortLinkMessaging`；local 走约定式路由，kafka 才 `DisableConventionalLocalRouting()` + `PublishMessage<T>().ToKafkaTopic()` + `ListenToKafkaTopics()`（只发不收等于把消息扔黑洞）。
- `Messaging/WolverineClickRecorder.cs`、`Messaging/Handlers/ClickRecordedHandler.cs`（静态 handler 接 `ClickRecorded[]`）、`Handlers/LinkClickCappedHandler.cs`。
- `IClickRecorder.Enqueue` → `ValueTask EnqueueAsync(...)`；删除 `Analytics/ClickEventQueue.cs`、`ClickEventFlushService.cs`。

### 踩坑（三个，都会让人卡住）
1. **`No routes can be determined for Envelope ...` = 静默丢消息**。`PublishAsync` 正常返回、不抛、不进死信。根因是 `DisableConventionalLocalRouting()` 关掉了「有本地 handler ⇒ 自动路由」的约定，而没显式声明目的地。**修法不是逐个 `LocalQueueFor<T>()`**（那只建队列不建发布订阅，仍无路由），而是：local 模式保留约定路由（消息类型 → 同名本地队列，与 `BatchMessagesOf` 的元素类型执行队列一致），只有 kafka 模式才关。
2. **`WolverineFx.RuntimeCompilation` 是独立包**。6.x 核心包不再内置 Roslyn，`TypeLoadMode.Dynamic`（开发默认）直接启动失败 `no IAssemblyGenerator`。
3. **`ServiceLocationPolicy.NotAllowed` 是 6.0 新默认值**。handler 注入 `ShortLinkDbContext` → `AddDbContext` 的 `DbContextOptions<T>` 是不透明 lambda 工厂，代码生成无法内联构造 → 启动期 `InvalidServiceLocationException`。修法：`wolverine.CodeGeneration.AlwaysUseServiceLocationFor<ShortLinkDbContext>()` 精确放行，**不要改全局策略**。

### 测试反模式修正
原来的 `await Task.Delay(3_000)` 把上面两个启动期故障伪装成了业务断言失败（`Expected Gone, Actual Found`）。统一换成 `WaitUntilAsync(condition, because)` 轮询：成立即继续、超时带 `because` 文案 `Assert.Fail`。

## 修正：高频点击事件不进本地消息表

用户要求「为了性能，高频的点击事件不要走本地消息表」。原实现里 `Messaging:Durable=true` 会调 `Policies.UseDurableLocalQueues()`，那是**全量** enrol，点击也跟着进 inbox —— 与文档写的「点击永远不持久化」不符。

### 改动
- 删除 `UseDurableLocalQueues()`，改为逐队列 opt-in（`MessagingSetup.ConfigureLocalQueueDurability`）：
  - `ClickRecorded` → `BufferedInMemory()`（无条件，与 `Durable` 取值无关）
  - `LinkClickCapped` / `LinkDisabled` → `UseDurableInbox()`（仅在 `Durable=true`）
- 同步更正 `MessagingOptions.Durable` 注释、README 配置表、AGENTS.md 约定、roadmap 技术债、ADR 0008 §3。

### 关键发现：`UseDurableLocalQueues()` 与单队列设置谁生效，取决于队列材料化时机
`AllLocalQueues` 注册的是 `LambdaEndpointPolicy`，启动期应用。踩坑时两者共存，结果是**点击照样进表**——`LocalQueueFor<T>().BufferedInMemory()` 写了也没用。所以不能「全量 durable 再把点击摘出来」，只能「默认全内存 + 逐个 opt-in」。

### 实测（`Messaging__Durable=true` + SQLite，真实宿主）
```
修复前  wolverine_incoming_envelopes: ClickRecorded × 6
修复后  wolverine_incoming_envelopes: LinkClickCapped × 1，ClickRecorded × 0
        11 次点击 → click_events=11，security_events=1，click_count/status 全对
```

### 踩过的坑：写了一个假护栏
先写了单测断言端点 `Mode == BufferedInMemory`，**把 `UseDurableLocalQueues()` 加回去后测试依然全绿**；换成数消息表行数（最小 `Host` + 派发一条点击）同样在 bug 存在时通过——最小宿主没复现完整宿主的端点材料化路径。两个版本都删掉了：在 bug 存在时通过的测试比没有测试更糟。已在 ADR 里写明这是**已知缺口**，只能靠手工重跑上面那个实验。

### 环境备忘
- Windows 上 SQLite 连接串必须用 Windows 路径（`Data Source=D:/...`），`/tmp/x.db` 会报 `SQLite Error 14: unable to open database file`。
- 后台跑 `dotnet run` 不要接 `| head`，管道关闭会 SIGPIPE 杀掉进程；重定向到文件即可。
- `ilspycmd` 装在 `~/.dotnet/tools/ilspycmd.cmd`（Git Bash 里要通过 `"$HOME/.dotnet/tools/ilspycmd.cmd"` 调用），查 Wolverine 内部语义很快。
- 验证：`dotnet test ShortLink.slnx` → **118/118**。

## 技术债 1/2/3 偿还（统计时区 / 缓存失效拓扑 / 来源地解析）

### #1 统计口径时区
- 新增端口 `IStatisticsCalendar`（`TimeZoneId` / `Today` / `ToDate(DateTime)`），实现 `StatisticsCalendar` 单例，构造时 `TimeZoneInfo.FindSystemTimeZoneById` 一次（IANA + Windows 双支持）。
- `ClickEvent.Create` 新增 `DateOnly clickDate` 参数——领域层不再自己 `DateOnly.FromDateTime`（领域层不该有时区知识）。
- 配置 `Analytics:TimeZone` 默认 `UTC`（**刻意等于旧行为**，升级不改历史分桶），`StatisticsOptions.Validate()` 启动期校验空值与无效 id。
- `ToDate` 对 `Unspecified` 按 UTC 处理：数据库读回的时间都是 `Unspecified`，当成本地时间会让同一份数据在不同机器算出不同日期。
- **补漏**：本轮还修了 `VisitorFingerprint.Compute` 的第三个口子——签名从 `DateTime utcNow` 改为 `DateOnly clickDate`，与 `click_date` 同源。原来 UV 去重按 UTC 日切，非 UTC 部署下「今日独立访客」会在 UTC 零点把自然日劈成两段、同一人算两次。

### #2 缓存失效范围（选择「轻量：收口为部署约束」）
- 明确**不做**跨实例失效广播：多实例本来就要求 Redis（限流也依赖），背板在时 FusionCache 通知已解决；广播丢一条/订阅阻塞会得到「部分实例失效」这种比「全部滞后一个 TTL」更难排查的状态。
- `ICacheTopology`（`Backplane` / `HasDistributedBackplane` / `LinkTtlSeconds`）单例，`/health/info` 与启动日志共用同一份判断；`LogCacheTopology` 在检测到 `KUBERNETES_SERVICE_HOST` 时打 `Warning`，单机打 `Information`。

### #3 地理信息
- `IGeoLocationResolver` + `GeoLocation(Country, Province)` record；两套实现：`HeaderGeoLocationResolver`（头名可配，默认 `CF-IPCountry`/`X-Country`、`X-Province`）、`MaxMindGeoLocationResolver`（`MaxMind.GeoIP2` 6.1.0，按 `Metadata.DatabaseType` 含 "City" 决定 `TryCity`/`TryCountry`，`Subdivisions[^1].Name` 取省，查不到回落头解析器）。
- **修掉一个隐性死分支**：原实现读取处做 HtmlEncode，条件路由拿编码后的值跟规则比对永不命中。编码属于渲染职责，采集处不编码。
- `GeoIp:DatabasePath` 配了但文件不存在 → 启动失败（静默回落的表现是「配了库省份还是空」，排查成本高）。

### 实测（真实宿主 5098 + SQLite）

```
click2 (CF-IPCountry: SG)                 → ('geo001','SG',None,'2026-11-11')
/health/info → {"cache":{"backplane":"in-process","crossInstanceInvalidation":false,"linkTtlSeconds":60},
                "statistics":{"timeZone":"UTC"}}
```

## 数据库设计文档（docs/database-design.md）

11 章：设计原则、表清单与 ER、9 张表逐表字段/索引/写入时机、关系与约束策略、多库差异、迁移策略与坑、查询→索引映射、已知缺口、容量估算、DDL 附录、术语。

**做法**：不手写 DDL，用 `dotnet ef migrations script` 对 Sqlite / MySql / PostgreSql 各生成一份真实脚本，再从产物里抄类型。这样字段类型、可空性、默认值、索引名全部与代码一致，也顺带暴露了跨库差异。

### 核对出的三个实际问题（已写入文档「已知缺口」）
1. **保留策略的过滤列没有索引**：`ClickRetentionService` 按 `clicked_at_utc < cutoff` 删，但 `click_events` 上只有 `(click_date)` / `(link_id, click_date)` 等，**没有 `clicked_at_utc` 索引**。代码注释写「按 ClickedAtUtc 而非 ClickDate 过滤：前者有索引前缀」，与实际索引不符——注释里的"前者/后者"应该是写反了。开启保留策略会走主键顺序扫描。
2. **`security_events` 未纳入 `workspace_id` 自动回填**：`DatabaseInitializer.BackfillWorkspaceAsync` 只回填 `short_links` 与 `click_events`。升级前的安全事件留在 `workspace_id=0`，而 `SecurityRepository` 按工作区过滤 → 后台看不到。需手工 SQL 或补进回填逻辑。
3. **MySQL 排序规则未指定**：DDL 只有 `CHARACTER SET=utf8mb4`，没有 `COLLATE`，MySQL 8 默认 `utf8mb4_0900_ai_ci` → `code` 大小写不敏感，仅大小写不同的两个短码被视为重复，与 SQLite（BINARY）/PG 行为不一致。基62字母表含大小写，上线前要确认是否需要 `utf8mb4_bin`。

### 其他记录
- SQLite 的 `decimal` 映射为 TEXT，`SUM(value)` 会走 REAL → 金额对账不要在 SQLite 做。
- PG 用 `timestamptz`，MySQL 用 `datetime(6)` 裸时间，SQLite 用 TEXT：三者物理表示不同，**库文件不能互换**。
- 全库只有一条物理外键（`link_routes → short_links` CASCADE），其余靠应用层；已在文档里写明代价（新增删除路径必须显式处理关联数据）。
- 索引共 20 条，与 model snapshot 的 `HasIndex` 计数一致。
