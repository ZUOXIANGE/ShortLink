# 业务码表

契约：`HTTP 200` + `{ "code": <业务码>, "msg": "<可展示文案>", "data": <载荷|null>, "errors": { "字段": ["错误"] } }`。

规则：

- `code` 与 HTTP 状态码解耦，客户端只能按 `code` 判定成败；
- 只能新增，不得复用或改变既有含义；`msg` 可随时调整文案；
- 新增码时同步更新 `src/ShortLink.Contracts/BizCodes.cs` 与本文档。

## 公共段

| code | 含义 | 典型场景 |
|------|------|---------|
| 200 | 成功 | 所有正常返回 |
| 20201 | 已受理 | 异步任务入队（当前未使用，预留给批量导出） |
| 40001 | 参数校验失败 | 见 `errors` 字段明细 |
| 40002 | 接口版本不受支持 | 版本段非 `v1` |
| 40101 | 未认证 / 令牌失效 | 未带令牌、令牌过期、签名不符 |
| 40301 | 无权限 | 已登录但角色不足 |
| 40401 | 资源不存在 | 路径不存在、方法不支持 |
| 40901 | 冲突 | 并发更新、唯一键冲突、短码生成失败 |
| 42901 | 请求过于频繁 | 登录 / 密码尝试 / 转化 / 举报 / MCP 超过各自配额 |
| 49901 | 客户端取消 | 浏览器主动断开 |
| 50001 | 服务器内部错误 | 未处理异常（响应不含堆栈） |

## 跳转链路的特殊约定

`GET /{code}` 是唯一对外提供真实 HTTP 语义的路径（浏览器、搜索引擎、CDN 需要真实状态码），映射关系：

| 业务码 | HTTP 状态 | 响应 |
|--------|-----------|------|
| 200 | 302 / 301 / 307 / 308 | `Location` 跳转（命中防红中间页时为 200 + HTML） |
| 13001 / 13004 / 13011 | 404 | HTML 落地页（不存在 / 已停用 / 尚未生效） |
| 13005 / 13012 | 410 | HTML 落地页（已过期 / 已封顶） |
| 13006 / 13007 | 200 | HTML 密码输入页 |
| 13016 / 13017 | 403 | HTML 拦截页（IP 不在范围 / 机器人拦截） |
| 50001 | 500 | HTML 落地页 |

判定顺序固定为：**点击封顶 → 启停状态 → 生效时间 → 过期时间 → IP / 机器人策略 → 访问密码 → 条件路由 → 防红中间页**。
先判封顶是因为「达阈值自动停用」会把状态改成停用，若先判状态，用户只会看到 404 而不知道是封顶所致。

`/health`、`/health/ready`、`/scalar`、`/openapi`、CSV 导出端点同样保留真实状态码（CSV 响应体不是信封）。
