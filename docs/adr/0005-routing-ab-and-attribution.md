# ADR 0005：条件路由、A/B 分流与转化归因

- 状态：已采纳
- 日期：2026-11-11
- 相关：`src/ShortLink.Domain/Links/RouteSelector.cs`、`src/ShortLink.Application/Redirection/RedirectService.cs`、`src/ShortLink.Application/Analytics/ConversionService.cs`

## 背景

平台需要在不改动已分发短链的前提下，让同一条短链对不同访客落到不同目标：

1. **条件路由**：按国家/省份、设备、浏览器、系统、语言、Referer、查询参数分流，且能组合（AND/OR）、有优先级、有兜底。
2. **A/B 实验**：同一条规则组内按比例分配，且**同一访客必须始终落到同一分支**——否则「加入购物车」和「结算」可能落进两个不同版本，实验结论不可信。
3. **归因**：不仅要知道「哪个分支点击多」，还要知道「哪个分支转化好」，且回调必须防伪造、防重放、防重复计数。

## 决策

### 1. 选择器是纯函数，不持有状态

`RouteSelector.Select(routes, context, fallbackUrl)` 只接受「规则快照 + 请求上下文」，返回「命中分支 + 目标地址」。规则以 `RouteSnapshot` 形式随短链一起进缓存，因此跳转路径上不需要再查库，也不依赖 EF 跟踪。

求值顺序：**按优先级降序分组 → 组内筛出命中项 → 组内有命中即结束 → 全部分组未命中则走兜底**。

### 2. 会话一致性用「确定性哈希」而不是「粘性会话」

同一优先级内多条命中时，取

```
bucket = SHA256(visitorKey | linkId | priority) % totalWeight
```

再按权重区间落桶。访客指纹由 IP + UA 派生，服务端不存任何会话状态，因此：

- 天然支持多实例水平扩容（不需要会话亲和）；
- 同一访客在同一短链上稳定落到同一分支；
- 不同短链之间互不干扰（`linkId` 参与哈希），避免「同一个人在所有实验里都是 A 组」的偏差；
- 优先级参与哈希，规则调整后流量会重新洗牌，这是预期行为（改规则本就意味着换实验）。

### 3. 条件组以 JSON 列存储，坏数据按「不命中」处理

条件不建宽表，`link_routes.conditions_json` 存 `{ "match": "all", "items": [{ "field", "op", "value" }] }`。解析失败返回 `null`，`ToSnapshot()` 直接把该分支标记为禁用——**坏数据不能让整条短链 404**。

运算符语义上的一个刻意选择：字段缺失时，只有 `neq` / `not_contains` 判为真，其余一律不命中。否则「未配置 country 的请求」会被误认为满足「country = CN」。

### 4. 转化回调：签名、时间窗、幂等三重约束

- **签名**：`X-Signature: sha256=hex(HMAC-SHA256(secret, "{X-Timestamp}.{rawBody}"))`。必须对**原始请求体**验签，因此端点先读字符串再反序列化——任何反序列化再序列化都会让空白/顺序变化导致签名不匹配。
- **时间窗**：`X-Timestamp` 与服务器时差超过 5 分钟即拒绝（15003），阻断重放。
- **幂等**：`(link_id, event_id)` 唯一索引；仓储层 `TryAddAsync` 把唯一约束冲突翻译成 `false` 返回值，应用层不必感知 EF 异常类型。重复提交返回 `duplicate: true` 且不增加计数。
- **密钥**：`conversion_secret` 不随短链详情下发，只在 `GET /links/{id}/conversion-key` 显式索取时返回一次（首次索取时生成）。浏览器端永远拿不到别人的密钥。

### 5. 跳转侧的判定顺序固定

```
点击封顶 → 启停 → 生效时间 → 过期时间 → IP/机器人策略 → 访问密码 → 条件路由 → 防红中间页
```

两个顺序细节值得记住：

- **封顶必须在启停之前**：封顶会把状态改成「停用」，若先判状态，用户只会看到「链接已停用」而不知道是达到上限。
- **密码在路由之前**：否则未通过密码验证的访客也能通过命中某个分支探知目标地址。

安全事件的写入用 try/catch 包住：审计失败不能把一次正常跳转变成 500。

## 后果

**正面**

- 跳转路径零额外查询（规则随缓存下发），单次跳转只做一次内存计算。
- 分流无需粘性会话，容器/多实例下行为一致。
- 转化数据可以按分支归因，A/B 结论可算转化率与转化价值。

**负面 / 代价**

- 分支统计需要在内存里把「点击（可空 RouteId）」与「转化（可空 RouteId）」两组小结果集对齐：.NET 字典拒绝 null 键，必须把 null 折叠成哨兵值 0（已由集成测试 `Stats_Should_Include_Fallback_Variant_Without_Blowing_Up` 锁定）。
- 路由保存是整表覆盖，分支主键会变，历史点击只能按分支名称归集（见 roadmap 技术债 6）。
- 访客指纹依赖 IP + UA，同一 NAT 后的多个真实用户会被视为同一访客；这是「无服务端状态」换来的必然妥协。
